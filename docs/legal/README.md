# Комплаенс 152-ФЗ — карта документов и статусов

Все документы в этой папке — рабочие шаблоны под PravoOS. Плейсхолдеры вида `{{ОПЕРАТОР}}`
подставляются из **[rekvizity.json](rekvizity.json)** — это единственное место, где заданы значения.
Сейчас там **фейковые реквизиты**; перед публикацией заменить их на настоящие и поднять
`PDN_POLICY_VERSION`. Сами `.md` не редактировать ради подстановки — они остаются шаблонами.

## Роли в обороте персональных данных

PravoOS выступает в **двух ролях одновременно**, и это принципиально для всей конструкции:

| Чьи данные | Роль PravoOS | Основание | Где реализовано |
|---|---|---|---|
| Юрист (пользователь сервиса): ФИО, e-mail, телефон, IP | **Оператор** | Согласие субъекта при регистрации | `user_consents`, модуль `privacy` в user-service |
| Клиенты юриста, стороны по делам, содержимое документов | **Обработчик по поручению** юриста (ст. 6 ч. 3 152-ФЗ) | Поручение в оферте + согласия, которые собирает сам юрист | `client_consents` в ai-service, раздел «Поручение» в [dpa-poruchenie.md](dpa-poruchenie.md) |

Из второй роли следует: **согласия клиентов собирает юрист, а не мы**. Наша обязанность —
дать ему инструмент (в карточке клиента) и зафиксировать факт получения согласия.

## Публикация во фронтенде

Документы с пометкой «Публиковать» копируются в бандл фронтенда скриптом
`frontend/scripts/sync-legal.mjs` (запускается автоматически перед `npm run dev` и `npm run build`)
и отдаются по адресам `/legal/privacy`, `/legal/consent`, `/legal/cross-border`, `/legal/cookies`.
Источник истины — файлы в этом каталоге; копии в `frontend/src/legal/` править нельзя.

Скрипт **падает**, если исходного документа нет или для плейсхолдера нет значения в
`rekvizity.json`. Это осознанно: молча опубликованный документ с `{{ЮР_АДРЕС}}` в тексте или
устаревшая копия из бандла — хуже, чем красная сборка.

## Что нужно сделать руками (кодом не закрывается)

1. **Заменить фейковые значения** в [rekvizity.json](rekvizity.json) на настоящие — один файл.
2. **Подать уведомление об обработке ПДн в РКН** — до начала обработки, форма из Приказа РКН
   № 180 от 28.10.2022, через [pd.rkn.gov.ru](https://pd.rkn.gov.ru) с УКЭП. Данные — в
   [uvedomlenie-rkn.md](uvedomlenie-rkn.md).
3. **Подать отдельное уведомление о трансграничной передаче** — до первой отправки данных
   получателям из [reestr-obrabotchikov.md](reestr-obrabotchikov.md), раздел 2: OpenAI, **Resend**,
   Sentry (США) и Telegram (ОАЭ). Передача возможна только после подачи; РКН вправе её запретить.
4. **Подписать приказ** о назначении ответственного за организацию обработки ПДн.
5. **Подключиться к ГосСОПКА** (или зафиксировать канал уведомления НКЦКИ) — нужно для
   уведомления об инциденте в течение 24 часов.
6. **Проверить договоры с подрядчиками** на наличие условия о поручении обработки и обязанности
   соблюдать 152-ФЗ (см. [reestr-obrabotchikov.md](reestr-obrabotchikov.md)).

## Плейсхолдеры

Полный перечень ключей и текущие (фейковые) значения — [rekvizity.json](rekvizity.json). Ключевые:
`{{ОПЕРАТОР}}`, `{{ИНН}}`, `{{ОГРН}}`, `{{ЮР_АДРЕС}}`, `{{ДОМЕН}}`, `{{EMAIL_PDN}}`,
`{{ОТВЕТСТВЕННЫЙ}}`, `{{АДМИНИСТРАТОР_БЕЗОПАСНОСТИ}}`, `{{РУКОВОДИТЕЛЬ}}`, `{{ХОСТИНГ}}`,
`{{НОМЕР_ПРИКАЗА}}`, `{{ДАТА_ПРИКАЗА}}`, `{{ДАТА_РЕДАКЦИИ}}`.

Новый плейсхолдер в документе без ключа в `rekvizity.json` роняет `sync-legal.mjs` — это гейт,
а не неудобство.

## Версии

Версия политики и согласия задаётся переменной `PDN_POLICY_VERSION` (по умолчанию `1.0`) и
пишется в каждую запись согласия (`user_consents.policy_version`). **При изменении текста
политики или согласия версию обязательно поднять** — иначе пользователи останутся с согласием
на старую редакцию, а доказать, с чем именно они согласились, будет нечем. После поднятия версии
сервис попросит пользователя переподтвердить согласие.
